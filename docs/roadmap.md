# slink 기능 로드맵

교수님 미팅(2026-06-01) 피드백 기반 — Colab 전용에서 범용 터널/DNS 플랫폼으로 확장.

---

## 핵심 방향

- **현재**: 외부(Colab)가 터널을 뚫고 SOLID VM이 접속
- **확장**: SOLID VM이 직접 역방향 터널을 유지 → 어디서든 VM 접근 가능
- **DNS**: 학생/팀별 서브도메인 발급 → `{학번}.solid.kr`

---

## 전체 기능 목록

### 1. 터널 & 연결

| 기능 | 명령어 | 설명 |
|------|--------|------|
| Colab GPU 연결 (현재) | `slink connect {코드}` | Colab JupyterLab을 VS Code 커널로 연결 |
| 역방향 터널 시작 | `slink up` | VM → Relay 상시 터널 유지 |
| 포트 공개 | `slink expose 8080` | 특정 포트를 외부에 공개 |
| 역방향 SSH | `slink ssh` | 외부에서 SOLID VM SSH 접속 가능하게 설정 |
| 터널 종료 | `slink down` | 터널 해제 |
| 상태 확인 | `slink status` | 현재 열린 터널·도메인·포트 목록 |

### 2. DNS 서비스

| 기능 | 설명 |
|------|------|
| 자동 서브도메인 발급 | `slink up` 시 `{학번}.solid.kr` 자동 등록 |
| 팀 도메인 | `{팀명}.solid.kr` → 팀 공유 VM 라우팅 |
| 커스텀 서브도메인 | 원하는 이름으로 신청 |
| DNS 자동 갱신 | 터널 재연결 시 엔드포인트 자동 업데이트 |

### 3. 용도별 서비스

| 용도 | 설명 |
|------|------|
| 웹앱 배포 | Flask, Django, Next.js 등 VM에서 외부 공개 |
| VS Code Remote | 집에서 SOLID VM 환경 그대로 접속 |
| DB 공유 | MySQL, PostgreSQL 터널링으로 팀원 공유 |
| 파일 서버 | VM 파일을 HTTP로 공유 |
| 팀 내부망 | 같은 팀 VM끼리 사설 네트워크 구성 |

### 4. 관리 & 인증

| 기능 | 설명 |
|------|------|
| 학번 기반 인증 | 학번/팀 코드로 세션 소유권 관리 |
| 세션 TTL | 터널 만료 시간 설정 (현재 12시간) |
| 다중 터널 | 포트별 여러 터널 동시 운용 |
| 사용 현황 대시보드 | 교수/관리자용 — 누가 무엇을 열었는지 확인 |
| 트래픽 제한 | 학생별 대역폭/포트 수 제한 |

### 5. 에이전트 (Colab 측)

| 기능 | 설명 |
|------|------|
| 자동 설치 | 원라이너 또는 `pip install slink-cli` |
| Colab 등록 | 터널 URL + Token → Relay에 자동 등록 |
| 헬스체크 | 터널 끊기면 자동 재연결 |
| 종료 정리 | Colab 종료 시 세션 자동 삭제 |

## 아키텍처 (확장 후)

```
[Colab / 외부 서비스]
        │  slink connect (현재)
        ▼
[Relay 서버 - Railway]  ◀── slink up (역방향)  ──  [SOLID VM]
   - 세션 관리                                          │
   - DNS 등록/갱신                                      ├── 웹앱 (8080)
   - 포트 라우팅                                        ├── JupyterLab (8899)
        │                                              └── SSH (22)
        ▼
[집/노트북/팀원]  →  {학번}.solid.kr  →  VM 서비스 접근
```

---

## 구현 우선순위

1. **역방향 터널 + `slink up`** — 가장 임팩트 큰 핵심 기능
2. **DNS 서브도메인** — 학생 경험을 확 올려줌
3. **`slink expose`** — 웹앱/DB 공개로 용도 확장
4. **대시보드** — 교수님/관리자 운영용

---

## 기술 선택지 (역방향 터널)

- `frp` (fast reverse proxy) — 가장 현실적, TCP/HTTP 모두 지원
- `rathole` — Rust 기반, 고성능
- SSH `-R` 옵션 — 간단하지만 안정성 약함
